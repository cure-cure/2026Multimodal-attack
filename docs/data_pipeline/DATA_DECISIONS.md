## 标签边界

- `image_adv_label`只表示有来源证据的对抗扰动，不表示图片本身有害。
- `harmful_content_label`表示用户请求是否请求有害内容；安全教育、新闻引用和拒答分析不能仅凭关键词标为1。
- `jailbreak_intent_label`表示是否有绕过模型约束、角色扮演越权或改变安全规则的意图。
- `prompt_injection_label`表示是否试图向模型注入更高优先级或改变模型行为的指令；它与普通有害请求可以同时为1。
- `overall_risk_label`在本主集按HoliSafe官方`type`第三位映射：U=1、S=0；这是来源标签，不是模型预测或目标模型越狱成功标签。SSU说明安全图片和安全文字也可能组合成风险输入。
- `harmful_content_label`按官方`type`第二位的query safety映射；`image_adv_label`、`jailbreak_intent_label`和`prompt_injection_label`保持未知空值，不能当作负例。
- HoliSafe的`type`依次表示图片内容、文字请求、整体输入安全性；`image_safe`不是`image_adv_label`，禁止把不安全图片直接标为对抗扰动。仅明确已核验的标签轴可非空，其余保留未知。
- 目标模型是否真的被越狱成功另设实验结果字段，不写入上述检测真值。

HoliSafe本地数据按官方定义将`type`第二位映射到query safety、第三位映射到final input safety。官方图片安全标注与图像对抗标签不同。五个图片路径在18条来源记录中出现`image_safe`/`image_safety_label`冲突；该轴仅保留原始记录，不用于本组监督目标。七组完全重复图像内容+请求已去重，冲突的overall标签数为0。

## 划分和去重

正式样本使用稳定 `sample_id`，按图片内容、用户文字和来源生成。相同图片、同一请求及其近似改写必须共享关联组并进入同一 split。跨数据集导入前至少进行图片 SHA-256、规范化文本和原始ID三类查重。

四种用途保持独立：`base_train` 用于B/C基础模型，`fusion_train` 只供D使用，`val` 用于阈值和配置选择，`test` 仅在配置冻结后由A评测。CIDER的原始`valset/testset`不直接映射到本项目的四种用途。

HoliSafe四划分从992个关联组生成，比例约50/20/15/15，并按overall风险、五种官方type和七个category作组级分层。精确像素/请求、dHash距离不超过4、至少6个词的规范化请求token Jaccard不低于0.85会合并为同组。该策略是自动启发式而非人工语义审核；分组参数与边表保存在`work/grouping_rules.json`、`work/near_*_groups.csv`。最终样本数为2002/808/605/609。

## 高质量实验需要满足的条件

1. 主实验正负例来自可比较场景，避免把数据源、图片路径、模板、语言直接当成类别捷径。按来源和场景分别报告，不能只报一个总准确率。
2. 保留单模态可判别与跨模态才可判别的子集。英文公开数据不能支持中文校园场景的泛化结论；自采数据暂缺按用户回复记录，后续有数据再补。
3. 同一图片的安全/危险请求一起分组；图像SHA和解码像素完全相同者不得跨集。当前近似图像/请求先按自动规则同组，仍需在报告中说明未人工复核语义改写和攻击模板。
4. 同源四集合可作课程内部实验；外部公开基准另留作迁移检查。不能把HoliSafe原test重新划分后仍称官方测试协议。
5. 每个划分须报告每标签有效数量、正负比例、独立组数、场景覆盖和未知项。软件的最低放行条件不等于高分保证。
6. CIDER对抗图片可能来自少量共同底图，不强求把它们拆满四份。独立性不足时保留为专项分析并报告局限，优先补已有公开攻击资源，不自行生成攻击。
7. 最终报告标注AI辅助代码和官方数据标签来源，由成员理解、复核并说明自主实现部分；不把工具自检当成自主算法实验成绩。
