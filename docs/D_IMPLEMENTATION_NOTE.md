# D 实现与协作说明

## D 当前完成项

D 已经完成可独立推进的代码工作：统一接口、模块加载、跨模态关联、基础融合、验证集选参、批量预测、三方案对比、本地演示页、结果记录和自动化测试。当前仓库可用脱敏示例证据完整跑通，但示例结果不能替代正式实验。

接口已强制区分“正常低分”和“模块不可用”：不可用模块不能携带风险分数，融合层也不会读取不可用模块的残留证据。该规则已有自动化测试覆盖。

## 与 A 的协作

A 保持数据清单和划分的唯一版本。D 只读取 A 的 `sample_id`、图片路径、用户文字、标签和 `split`，不做原始数据清洗或重划分。

D 向 A 交付逐样本 JSONL，包含预测、风险分数、阈值、模式、各分量分数、证据来源、警告和模块版本。A 据此统一计算准确率、误报与漏报，并组织失败案例。

## 与 B 的协作

B 负责图片预处理、OCR、视觉特征和失败样本。D 只消费 `ImageEvidence`，不解释或重算 B 的底层特征。B 可以选择在线 Python 接口或离线 JSONL。

对接时重点检查：OCR 失败是否与“没有文字”区分，视觉异常分数是否在 `[0, 1]`，文字区域与模块版本是否保留。

## 与 C 的协作

C 负责文本规则基线和自主文本分类算法。D 只消费用户文字、OCR 文字、组合文字三类风险分数及依据，不在融合层复写关键词规则或训练文本分类器。

对接时重点检查：三个分数是否分别输出，缺失 OCR 时是否写明原因，证据位置是否能用于页面展示。

## D 的第一次汇报建议

建议按以下顺序演示：

1. 用一张图说明完整流程和 A/B/C/D 边界。
2. 展示统一接口，强调 `sample_id`、`available`、分数范围和可解释证据。
3. 展示页面在 B/C 正常与缺失时的两种状态。
4. 用公式说明跨模态分数、加权融合、视觉权重上限。
5. 演示验证集拟合命令和拒绝测试集调参的保护。
6. 演示批量 `compare` 输出，说明最终指标由 A 统一计算。

## 正式联调顺序

1. A 冻结训练、验证、测试清单和字段。
2. B、C 先用 5 到 10 个共同样本验证接口。
3. D 运行接口校验与批量预测，修复缺失和编号不一致。
4. 只在验证集运行 `fit`，确认并冻结配置文件。
5. 在测试集一次性生成三方案结果，交给 A。
6. A 汇总指标；B、C、D 分别解释与本模块有关的失败案例。
