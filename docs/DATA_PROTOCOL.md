# 数据用途与隔离约定（D 提案，待 A 确认）

依据最新分工，A维护数据、标签及划分，D只读取。本文给出可执行字段，不能代替 A 的正式数据包或成员确认。

| split | 使用人及用途 | 禁止事项 |
| --- | --- | --- |
| base_train | B/C训练基础模型、拟合特征变换 | 不用融合训练或测试数据训练基础模型 |
| fusion_train | D使用冻结 B/C 的预测训练融合参数；缺失值统计也只在这里拟合 | B/C不得在这部分继续训练基础模型 |
| validation | B/C选参数；D选融合阈值及预先约定的候选方案 | 不当作 D 的梯度训练数据 |
| test | A使用冻结模块、融合参数及阈值评测 | 不选模型、不调权重、不调阈值 |

同一图片、近似图片、相似请求及其变体必须同组划分。清单每行至少提供 `sample_id`、`image_path`（可为null）、`user_text`、`split`、`source`、`image_group_id`、`request_group_id`。两种组号中的任意一种相同均不得跨划分；连通的图片组和请求组整体划分，由A负责。缺图记录保留状态，不能冒充图像已处理。

标签分别保留 `harmful_label`、`jailbreak_label`、`image_adversarial_label`（均为0/1/null），整体 `label` 的映射规则由A写入数据说明并全组确认。不把图像扰动自动等同于整体风险。不确定标签为null；训练及评测需排除并报告数量。仅图像结果对照 `image_adversarial_label`，仅文字与完整融合对照整体 `label`。

`validate` 检查上述七个必需字段是否存在及其类型、四种split、编号唯一性、组号是否跨划分、标签类型和B/C文件编号集合。user_text允许空字符串，image_path缺图时显式为null；source必须为非空字符串。运行时可读取A合并的全量清单。它不检查图片文件是否实际存在、不自动识别图片近重复、不判断标注对错，也不重新划分。仅校验部分文件不能证明整个数据集没有泄漏。

旧 `fit` 是验证集权重/阈值网格搜索实验工具，仅供旧原型和模拟调试；不能当作本计划的“融合训练集训练+验证集选阈值”已完成。正式训练链路按 [融合路线](FUSION_ROADMAP.md) 在第四周实现、第六周使用真实稳定分数训练。现阶段固定配置使用未验证权重及0.5阈值，只验证软件流程。

待 A 确认：四种split命名、组号生成规则、三类标签与整体label映射、数据清单版本、各划分是否均有有效正常/风险样本、最终测试访问方式。A尚未确认，不填写虚构比例或样本量。
